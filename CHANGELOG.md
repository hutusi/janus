# Changelog

All notable changes to this project are documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Run-history retention** — a new `history_limit` (`--history-limit`) caps how many terminal runs are kept; when exceeded, the oldest terminal runs and their logs are pruned after each run finishes and at startup (running/pending runs are never pruned). `0` (the default) keeps everything, so an upgrade never deletes history until you opt in. This also bounds the flat-file store's list/startup cost, which reads every run directory.
- **Run-list pagination** — `GET /api/runs` accepts `?offset=` alongside `?limit=`, returning a newest-first window so clients can page through history.
- **Persistent workspaces** — `workspace_strategy: persistent` (`--workspace-strategy`) gives each repo one reusable janus-owned workspace, updated in place with `git fetch` + `git reset --hard`, so untracked dependency and build caches (`node_modules`, incremental output) survive between runs — hermeticity deliberately traded for speed, opt-in only. Concurrent runs of one repo are serialized by a per-repo try-lock; a contending trigger falls back to a fresh per-run clone rather than blocking. `persist-*` directories survive restarts and the startup sweep; any git failure in the reuse path self-heals by rebuilding the directory. `fresh` (per-run directories) remains the default.
- **Scripted uninstall** — `deploy/install.sh uninstall` (or `make uninstall-service`) stops and disables the service and removes the unit and binary, keeping `/etc/janus`, `/var/lib/janus`, and the `janus` user so no data or secrets are destroyed by surprise; `--purge` removes those too. Supports `--dry-run` like the installer.
- **`make install` / `make uninstall` / `make install-service`** — `make install` places the built binary in `$(PREFIX)/bin` (default `/usr/local/bin`; `DESTDIR` supported), and `make install-service` provisions the Linux systemd service from the local build by wrapping `deploy/install.sh --binary` (extra script flags via `INSTALL_FLAGS="..."`). `install` deliberately does not rebuild, so `sudo make install` never runs the Go toolchain as root.
- **`branches-ignore` trigger filter** — `on.push` and `on.merge_request` accept `branches-ignore: [...]`: run on every branch except the listed ones (exact string match, like `branches`). Declaring both `branches` and `branches-ignore` on one trigger is a validation error — pick an allowlist or a denylist.
- **Per-trigger pipeline file** — `POST /api/trigger` accepts an optional `pipeline_path` field selecting a committed pipeline file other than the configured default for that one run, named relative to the configured file's directory (`"release.yml"` → `.janus/release.yml`; subdirectories allowed). Absolute paths and `..` escapes are rejected with `400` before anything is cloned, and the override is recorded on the run's event, so `GET /api/runs/{id}` shows which file ran. Webhooks keep using the server-wide `pipeline_path`.
- **Windows support** — pipeline steps can run on native Windows. The step shell now depends on the host (`/bin/sh` on unix, `cmd` on Windows) and is overridable with a new step [`shell:`](docs/pipeline-reference.md#step-shell) key (`sh`/`bash`/`cmd`/`powershell`/`pwsh`). A `janus-windows-<arch>.exe` binary is published, and a `windows-latest` CI job guards execution (process-tree kill uses the built-in `taskkill`, so no new dependency). Pipelines are no longer portable across OSes; the systemd unit and `deploy/install.sh` remain Linux-only.
- **Scripted install** — [`deploy/install.sh`](deploy/install.sh) provisions Janus as a systemd service in one command: it detects the architecture, downloads and checksum-verifies the release binary, creates the `janus` user, writes an idempotent config plus a `janus.env` with generated secrets, and enables the unit. Supports `--allow-repo`, `--version`, `--dry-run`, and an `upgrade` mode; linted by `shellcheck` in CI.
- **Offline install** — `deploy/install.sh --binary <path>` installs a locally-built binary and makes no network access at all (no release download or remote checksum), for air-gapped hosts. `upgrade` accepts it too.
- **Linux deployment** — a hardened `systemd` unit ([`deploy/janus.service`](deploy/janus.service)) and secret template ([`deploy/janus.env.example`](deploy/janus.env.example)), plus a [deployment guide](docs/deployment.md) for running Janus as a dedicated-user service.
- **Example pipelines** — [`examples/build.yml`](examples/build.yml) (build on every master update) and [`examples/release.yml`](examples/release.yml) (build, then publish the output to a separate pages repo), with an [`examples/README.md`](examples/README.md) covering the push-vs-MR-merge trigger, the shallow checkout, and host SSH auth. Validated in CI.

### Changed

- **Job names are restricted to `[A-Za-z0-9_-]`** — previously any map key was accepted, but the store derives each step's log-file name from the job name via a lossy sanitizer, so distinct names like `a/b` and `a?b` collapsed to the same file and interleaved their logs. Pipelines using other characters in job names must rename them.
- **Example pipelines** — [`examples/build.yml`](examples/build.yml) now triggers on every push except `master` (`branches-ignore`) and builds the pushed branch via `git fetch --depth 1 origin "${{ branch }}"`; [`examples/release.yml`](examples/release.yml) keeps publishing `master`. The examples README's manual-release command uses the correct `janus run --file` flag.

### Fixed

- **Whole-run log snapshots stream instead of buffering** — `GET /api/runs/{id}/logs` (the aggregate view) previously read every step's log fully into memory via `io.ReadAll`; it now streams each step directly to the response, bounding memory for large runs. (The HTML run page still renders logs into the page, now bounded by `history_limit`.)
- **Terminal run-state writes are retried before the record is abandoned** — a transient failure (full or briefly read-only disk) persisting a run's *final* status would strand the stored run non-terminal forever, which startup reconciliation then records as `cancelled` even for a run that actually succeeded. The terminal write now retries a few times before giving up and logging at error level.
- **Allowlist distinguishes git authorities** — URL normalization now keeps userinfo, so `ssh://git@host/acme` no longer matches `ssh://root@host/acme` (git connects as different users), and `git://`'s default port is corrected to 9418 (was treated as ssh's 22).
- **Manual-trigger JSON rejects all trailing data** — the trailing-data check used `encoding/json`'s `Decoder.More()`, which returns false for a trailing `]`/`}`, so `{…}]` slipped through; it now requires a second decode to reach `io.EOF`, matching the strict YAML parsers.
- **Installer fails when the service is active but never serves** — after ten failed health probes (curl present) the installer warned and returned success, then announced Janus "running"; it now aborts the install with a `journalctl` pointer.
- **Git option injection through trigger-supplied SHA/ref closed** — a manual trigger or webhook could set `sha`/`ref` to values git parses as options (e.g. `--upload-pack=/bin/sh`), executing an arbitrary program during `git fetch` and bypassing the commit verification. The workspace now validates the SHA as 7–64 hex characters and the ref against a conservative git-ref grammar before any git process runs (rejecting leading `-`, `..`, `@{`, trailing `.lock`/`/`, and the like). The 7-char SHA minimum also rejects ambiguously short prefixes. Each run now records the full resolved `HEAD`, so metadata, `${{ sha }}`, and `JANUS_SHA` name the exact 40-char commit even for abbreviated or ref-only triggers.
- **Graceful shutdown tracks and cancels checkout/parse work** — admission now enrolls a trigger in the shutdown wait *before* the checkout, and the checkout runs on the runner's context, so a shutdown that times out mid-checkout waits for (and then kills) the git process instead of returning while it runs on. This also removes a `sync.WaitGroup` misuse where `Add` could be called after `Wait` had returned. New triggers are rejected with `503` once shutdown begins.
- **Installer verification fails on an inactive service** — `deploy/install.sh` printed `systemctl is-active`'s output but discarded its exit code, so with curl unavailable (offline `--binary` installs) verification reported success even when the service never started. An inactive service now aborts with a pointer to `journalctl`.
- **Log following no longer re-reads the whole file every poll** — the `?follow=1` stream re-read the entire log from disk every 300ms and discarded the already-sent prefix, an O(n²) disk workload for long chatty steps. `Store.ReadLogs` now takes a byte offset (file store seeks; memory store slices), and the follower reads only what appended since the last tick.
- **Crash-orphaned runs no longer display as running forever** — runs left `pending`/`running` by a crashed or hard-killed daemon are marked `cancelled` at the next startup (running jobs/steps → `cancelled`, never-started work → `skipped`), so the dashboard stops refreshing them indefinitely and log followers terminate.
- **Graceful shutdown always stops build processes** — if HTTP shutdown exceeded its 10s deadline (one lingering log-follow connection sufficed), `janus serve` returned without ever cancelling in-flight runs, exiting with build process groups still alive — contradicting the drain behavior the systemd unit documents. The runner now shuts down unconditionally. `janus run` similarly ignored Ctrl-C: it now wires the signal into the engine so interruption drives the process-group kill and the run is recorded `cancelled`.
- **Externally-cancelled runs are recorded as `cancelled`, not `failed`** — shutdown/interrupt previously coarsened the run status to `failed` even though jobs and steps already used `cancelled`; a fail-fast run (one job genuinely failing) still reports `failed`. A failure to persist a run's *terminal* state is now logged at error level (there is no later write to self-heal it); intermediate persist failures remain warnings.
- **Trigger bursts can no longer start unbounded work** — checkout, pipeline parsing, and the pending-run queue now count against a bounded admission pool (4× `max_parallel_runs`; previously only *executing* runs were capped, so a burst could spawn unlimited git processes and workspaces). When the pool is full, webhooks and `POST /api/trigger` answer `503` with `Retry-After` so providers retry the delivery instead of piling up.
- **HTTP request hardening** — the webhook body cap now rejects oversized payloads with `413` instead of silently truncating them into a misleading signature failure (`401`); `POST /api/trigger` gets a 1 MiB body cap, rejects unknown JSON fields and trailing data, and the server sets `ReadTimeout`/`IdleTimeout` so a slow request body cannot pin a connection open indefinitely (`WriteTimeout` stays unset deliberately — log following is a long-lived response).
- **Strict parsing gaps closed** — a pipeline or config file containing a second YAML document (`---`) is now an error instead of the extra document being silently ignored; an unterminated `${{` placeholder is now a validation error instead of reaching the shell verbatim; and `janus serve` rejects nonsense configuration at startup (negative `max_parallel_runs`/`max_parallel_jobs`/`step_timeout`, explicitly empty `workspace_root`/`pipeline_path`) instead of silently reverting to defaults — notably a negative `step_timeout` used to mean *no timeout*.
- **Checkout can no longer silently run a different commit than the trigger records** — when a Git server refuses fetch-by-SHA, the checkout falls back to fetching the ref; if the branch moved (or was rewritten) between the webhook and the checkout, Janus would execute the new tip while the run's metadata, `${{ sha }}`, and `JANUS_SHA` still named the event's commit. Both fresh and reused (persistent) checkouts now verify `HEAD` against the requested SHA and fail the run on a mismatch. Abbreviated SHAs from `janus run` match by prefix.
- **Allowlist path traversal closed** — repo URLs containing `.` or `..` path segments, literal or percent-encoded (`%2e`, `%2f`, `%25`), are now always denied: git, HTTP infrastructure, or the filesystem could resolve such segments *after* the prefix match, letting `https://host/acme/../evil/repo` slip past a `https://host/acme` entry (worse for local-path remotes, where `..` walks the real filesystem). Allowlist entries containing them are now a startup error.
- **systemd hardening now actually applies** — the balanced sandbox in [`deploy/janus.service`](deploy/janus.service) had trailing inline comments on its directive lines, which systemd parses as part of the value and silently ignores. `NoNewPrivileges`, `ProtectSystem`, `ProtectHome` and `PrivateTmp` were all being dropped (confirmed via `systemctl show`); the comments moved to their own lines so every protection takes effect. CI now rejects inline-comment directives in `deploy/*.service`.

## [0.1.0] - 2026-06-26

### Added

- **Pipeline engine & CLI** — a small GitHub-Actions-flavored `.janus/ci.yml` with strict validation (unsupported keys and expressions are errors, not features), a DAG scheduler that runs independent jobs concurrently and is fail-fast, and a host-process step executor that streams combined stdout/stderr to the store. `janus validate <file>` and `janus run <dir>`.
- **Server & triggers** — `janus serve` exposes a GitLab webhook endpoint (push + merge request), a manual HTTP trigger, a JSON API, and a read-only HTML dashboard. Each run shallow-checks-out the triggering commit into a per-run workspace.
- **Persistence** — a restart-safe flat-file run/log store, plus an in-memory store for the CLI and tests.
- **Hardening** — per-step process-group kill, step timeouts, run/job concurrency caps, graceful shutdown, and bearer auth on `/api` (mandatory for `POST /api/trigger`).
- **YAML config file** — `--config` (and auto-load of `./janus.yml`) covering all `janus serve` settings, with precedence defaults < file < env < flags. `janus init` scaffolds an annotated `janus.yml`.
- **Repository allowlist** (`allow_repos`) — deny-by-default with a `*` allow-all escape hatch; a repo not on the list is rejected with `403` before any checkout. Defense-in-depth against a leaked webhook secret or API token.
- **`CLAUDE.md`** — concise guidance for AI coding agents.
- **MIT license.**

### Changed

- The example config now defaults `data_dir`/`workspace_root` to a cwd-relative `./janus-data` (created on demand, no sudo) instead of `/var/lib/janus`.
